### 🎯 Project goal

Create an automated DevOps solution in **AWS Ireland (eu-west-1)** that:

- stores source code in **GitHub**;
- uses **Jenkins on EC2** for CI/CD, triggered by a **GitHub webhook**;
- builds **versioned Docker images** using the **Jenkins build number** + Git short SHA;
- stores images in **private Amazon ECR**;
- runs the **presentation web app** on **Amazon ECS with AWS Fargate** (never on EC2);
- puts an **NGINX reverse proxy** in front of the application;
- performs **blue/green deployment** with **two app containers** and **switches traffic only after a successful health check**;
- exposes the application publicly through an **Application Load Balancer**;
- creates all infrastructure with **Terraform**, using a **remote S3 backend + DynamoDB state locking**;
- configures the Jenkins EC2 with **Ansible**;
- stores **AWS credentials (and any registry/webhook secrets) in Jenkins Credentials**;
- collects **logs, metrics, and alarms in CloudWatch**;
- provides a **full draw.io architecture picture** and **complete documentation**;
- **logs all AI usage** and surfaces it inside the presentation app;
- can be **safely destroyed** with `terraform destroy` after the demo.

### 🏗️ Agreed architecture (v2 — with NGINX proxy + blue/green)

```
Developer
   │  git push
   ▼
GitHub repository ──webhook──► Jenkins on EC2 (configured by Ansible)
                                   │
     ┌─────────────────────────────┼───────────────────────────────────┐
     │ validate → prepare metadata → build image → local container test │
     │ security scan → tag (BUILD_NUMBER-gitsha) → push to Amazon ECR    │
     │ deploy GREEN → wait for GREEN health → switch NGINX to GREEN      │
     │ smoke test public ALB URL → scale down BLUE → archive evidence    │
     └─────────────────────────────┬───────────────────────────────────┘
                                    ▼
                               Amazon ECR (private, immutable tags)
                                    │  Fargate pulls image
                                    ▼
                    ┌──────────────────────────────────┐
Internet ─► ALB ─►  │  NGINX reverse-proxy (Fargate)   │  ← the "front" + traffic switch
                    │        upstream → active color    │
                    └───────┬───────────────┬──────────┘
                            ▼               ▼
                   app-BLUE (Fargate)   app-GREEN (Fargate)
                   presentation SPA     presentation SPA
```

**Blue/green mechanism (agreed):** the NGINX reverse proxy is *both* the required proxy tier *and* the traffic switch. Two app containers (`app-blue`, `app-green`) always exist as separate Fargate services. Jenkins deploys the new color, health-checks it **directly**, and only then reconfigures NGINX to point its `upstream` to the new color and reloads. The old color stays warm for instant rollback, then is scaled down. This satisfies "two Docker containers and switch traffic after a successful health check" in one teachable mechanism.

> 🟡 Alternative acceptable design: ALB with two target groups + AWS CodeDeploy for ECS blue/green. We chose the NGINX-switch design because it *also* satisfies the NGINX reverse-proxy bonus and is easier to explain live. This is recorded as a design decision.

Supporting services:
- Terraform **S3 remote state + DynamoDB lock table**
- IAM roles and policies
- VPC, public/private subnets, routing, security groups
- CloudWatch Logs, metrics, and **alarms**
- Ansible configuration for Jenkins EC2
- **Jenkins Credentials** store for AWS keys + webhook secret

### ✅ Project Definition of Finished

**Infrastructure**
- Terraform creates eu-west-1 environment using **remote S3 state + DynamoDB lock**.
- Jenkins runs on EC2; the web app never runs on EC2.
- Images stored in private Amazon ECR (app + proxy).
- App runs as **blue/green ECS Fargate** services behind an **NGINX reverse proxy** behind an **ALB**.

**Configuration**
- Ansible configures Jenkins EC2; Docker + AWS CLI work as the Jenkins user; plugins installed; second run idempotent.
- **AWS credentials + webhook secret stored in Jenkins Credentials.**

**Application**
- The presentation SPA builds into a Docker image and documents the week's work.
- Health + version endpoints work; `/version.json` shows build number, commit, and active color.

**Pipeline**
- GitHub webhook triggers Jenkins.
- Jenkins validates, builds, tests, scans, and **versions** the image.
- Jenkins pushes immutable images to ECR.
- Jenkins deploys **GREEN**, health-checks it, **switches NGINX after success**, smoke-tests the ALB, scales down BLUE.
- Evidence archived.

**Security & monitoring**
- No secrets in Git; no Docker Hub references.
- CloudWatch logs + **alarms** (ALB 5xx, unhealthy targets, CPU) documented.

**AI governance**
- Every AI action logged with platform + model; prompts captured; AI code blocks marked; how/why explained; rendered in the app.

**Documentation**
- **draw.io** picture matches deployment; full docs cover deploy, blue/green, troubleshooting, monitoring, AI usage, teardown.

**Cleanup**
- Webhook disable → reviewed `terraform destroy` → leftovers checked → backend retention decided.
